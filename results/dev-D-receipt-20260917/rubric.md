# 人工评分与客观检查

评估对象是 **DSH 的内联组件及同次回答正文**。Codex/Cowork 只作产品参照。其它任务只检查路由，不评分代码、文件或扩展的质量。

## 先看完成情况，再分别评质量

客观检查分别记录：路由、Host 准入、初次渲染、数据和状态、局部操作、追问内容。完整 Web 追问及原位修复另列，独立预览不能证明这些链路完成。

- `pass`：有证据满足该检查。
- `fail`：有证据违反题目的要求。
- `pending`：尚未检查，或自动化不能判定，需要人工核对。
- `error`：环境、运行器或检查器出错；不冒充模型失败。
- `not_applicable`：该题没有这项要求。

`accepted` 不等于渲染成功；`rendered` 不等于内容正确；找到按钮不等于按钮工作。首次失败保留，后续修复成功不能覆盖首次结果。环境失败单列，并保留在计划/尝试数中，不能静默重跑挑最好的一份。

## 四维 0 / 1 / 2

每份分别评价，隐藏候选版本。完整正文、全部组件、题目和预期结果一起展示。评分不相加为总分，也不以美观抵销事实或功能错误。

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 理解价值 `understanding` | 看不清要表达的关系 | 配合正文才能理解 | 视觉直接呈现关键关系或变化 |
| 信息与布局 `layout` | 关键内容难读、遮挡或层次混乱 | 能读懂，但局部拥挤或层次不清 | 内容清楚、协调，重点突出 |
| 操作可理解性 `operability` | 不知道怎么操作或当前是什么状态 | 摸索后能使用 | 入口、当前状态和反馈含义清楚 |
| 简洁与聚焦 `focus` | 无关内容明显干扰主要任务 | 有冗余，但主要内容突出 | 内容集中，图与正文各有作用 |

### 不适用与未评

- 没有操作要求的静态图，操作维度填 `n/a`，说明“静态图，无操作要求”。
- 完全无法渲染时，无法观察的维度填 `n/a` 并说明原因；渲染失败另有客观记录。
- 要求的操作缺失，应记录功能失败，不能借“静态图”豁免。
- 未填写不等于 0；没有人工标注时不计算人工质量结果。
- 内容错误与呈现分别判断。例如按钮名称清楚但点击报错，功能失败不自动把布局分改成 0。
- 同一个问题尽量只影响最直接的维度；不要因一处拥挤机械地将四维全扣分。
- 纵向滚动、多张图或使用特定颜色不自动判失败；判断它是否妨碍这道题的目标。

## 每份的操作步骤

1. 阅读 query 和预期结果，查看组件与完整正文。
2. 有控件时实际操作：初态、关键中间状态、终态，以及题目要求的重置/边界。
3. 在 736px/360px、浅色/深色下查看。自动溢出标记仅是提醒，不代替判断。
4. 核对事实；可以沿用已核验的证据，但不把机器检查当成人工分。
5. 填四维和必要说明，保存。能确认的客观问题可在备注指出；不确定的保留待核。

评分绑定题面、全部原始组件、同次正文、预览、渲染版本和评分规则/页面版本。内容改变后必须重新评价，旧记录仍保留。

## 校准例子与迭代

校准的 6 份样本来自历史 integrated 版本，每题两次独立生成，**不是新旧提示词 A/B**。二分查找的“8 个元素最多比较 3 次”是已知正文错误；另一份命中后仍显示候选数，是状态表达不一致。热传导和地区追问可用于检查数值和消息的判分方式。

先试标这些样本，对有分歧的锚点改清楚，再冻结正式评分规则。若以后增加模型裁判，须用另一批人工样本逐维核对误判；同一模型三票不等于三名独立专家。首版不采用未经校准的模型质量分。

开发集用于解释失败并调整工具指导/Skill；测试集在候选冻结后运行。普通 master 与加入两个 PR 的版本用于路由保护对照；当前 PR 与提示词候选用于内联效果对照。可主动生成的题允许文字和内联两种形式，出图率仅描述行为，不能作为质量奖励。

## 来源与适配

本规则依据用户提供的评测设计稿，结合本机实际安装的 Codex Visualize Skill 1.0.32 中的构图、交互和可访问性规则，以及 Claude skill-creator 的 grader/analyzer 方法细化。四维锚点是本 benchmark 的定义，不是官方评分表。

借鉴 [DSH file-references 的证据与标注绑定](https://github.com/Dudu-0223/dsh-benchmarks/tree/main/file-references)、[Anthropic agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 和 [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。不要求采用其它宿主专属的 CSS、DOM 结构或工具。
