REST vs GraphQL · 移动端接口取舍
选一个团队现状，看推荐与理由

REST 推荐

资源导向 · 约定优先 · 基建几乎为零

  • 上手成本路径 + 动词即全部心智模型，新人当天能提交接口
  • 移动收益HTTP 缓存 / CDN / ETag 直接可用，省流量省电
  • 主要代价聚合靠 BFF 或多次往返；字段多了易接口膨胀
  • 运维面无网关、无 resolver，看日志就能定位问题
  • 演进/v1 /v2 并行，老客户端留在旧版本更省事

GraphQL 备选

契约导向 · 单端点 · 需要持续投入

  • 上手成本schema / resolver / 前端 client 一套都要学，约 2 周起步
  • 移动收益一屏一次请求精准取数，慢网下明显少一次往返
  • 主要代价N+1、查询深度、响应体积必须主动设限
  • 运维面网关 + 逐字段鉴权 + 可观测，都是长期税
  • 演进单版本 + @deprecated，但客户端缓存更难做对
